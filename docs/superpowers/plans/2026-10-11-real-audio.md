依据：need.txt、需求开发文档.md。用户最新授权：缩小界面，直接接真实数据，全部功能完成后再交付；覆盖先确认 UI 和逐模块交付的旧流程。

## 架构与边界

原生 Rust + Win32/GDI 保留；面板改为 360 逻辑像素宽，单行 44，高 DPI 仅缩放一次。无新增第三方 crate。音频对象集中在独立 MTA 线程，回调只唤醒该线程；界面通过命令通道与不可变快照交互。空闲阻塞等待事件，不做定期轮询。

## 任务

- [x] COM 和 Core Audio：枚举全部活动播放设备与会话、设备/应用静音与音量、设备和会话增删/外部音量通知。
- [x] 音量规则：显示实际设备值与有效应用音量；应用与设备相同则跟随，独立较低音量保持目标；主音量降低后重新升高恢复独立目标。
- [x] 播放策略：系统默认三角色，按应用保存输出设备；设备离线回退默认，重连恢复偏好；未指定设备的应用随默认切换。
- [x] 持久化：配置按稳定设备 ID 和应用路径保存，原子替换；注册表当前用户 Run 开机启动，系统新旧设置入口。
- [x] 紧凑正式 UI：移除 mock 标签与状态菜单，显示真实状态和错误；保留折叠、滚动、键盘、托盘、应用设备菜单，持久化折叠。
- [x] 源码审查、release 编译、固定 EXE 覆盖、更新日志和 README；不运行测试、不启动应用。

## 平台风险处理

应用路由与设置默认设备依赖 Windows 内部 COM 接口，参照项目原始接口定义核实 ABI，并提供 Win10 / 21H2+ 两个工厂 IID。返回值失败必须告知用户，不能凭 UI 移动伪装成功。音频引擎最终设备位置从实际会话重新枚举获得。

用户明确要求直接开发并最终交付，因此本计划在当前会话执行，不再次请求设计或预览批准。只在不可替代的信息/权限阻塞时提出问题。
