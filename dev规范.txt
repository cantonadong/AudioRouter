## UI / Animation Preview First Rule

凡涉及 UI、布局、样式、动效、交互反馈的修改，必须先做可预览版本，再写入真实业务逻辑。

要求：

1. 先创建或更新独立 Preview / Playground / Demo 页面，不依赖真实接口、登录、数据库、权限或完整打包流程。
2. UI 必须使用 mock data 还原最终效果，至少覆盖 normal、loading、empty、error、edge case 状态。

## Git 同步规则

只使用 `main`，不创建其他分支。修改前拉取并确认本地 `main` 与 `origin/main` 提交一致；修改后提交、推送全部必要项目文件，再次确认两者提交一致且工作区干净。版本只用 tag 标记。
